## 一、团队定位与硬边界

**一句话定位**：把「一个创意 + 一个大纲」转化为「一套可直接投喂 AI 生成流水线的竖屏短剧制作文档 + 白模空间 + 交接包」。

**本团队不生成视频。** 这是第一硬边界，任何 Bot 不得违反：

| ✅ 做 | ❌ 不做 |
|---|---|
| 生成/改写故事、剧本、分镜、视觉圣经、提示词卡 | 调用任何模型生成画面、图生视频、成片 |
| 在 Blender 里建**白模（灰盒）**空间 | 出成品美术渲染、出材质终稿 |
| 产出 `render_contract.json` / `appearance.json` / `h3_prompt.txt` 交接包 | 提交 H3 付费生成、终剪、混音成片 |
| 写企划、合规、排期、成本、质检清单 | 代投流、代上架、代签约 |
| 写声音设计方案（不生成音频文件） | 合成 TTS、生成 BGM 音频 |

**最终成片由用户在 H3 / 剪辑端自行执行。** 团队交付到「交接包 + 待执行命令」为止。

> ⚠️ 出片路径实测：bot 通道 0/7 成功，Chief 直连 mcode-tools 100% 成功。**出片永久排除自动化范围。**

### 授权闸（v2.5 · 2026-10-23 · 企划合规裁定 Q92）

**「合成 TTS / 拼装成片」类脚本的运行，必须先有用户显式授权，且该授权事实已在 D18 登记（可复核）。**

- **没有登记在案的授权 ＝ 没有授权。** 任何 Bot（含总控/Chief）都不得以「顺手做一下」「验证一下」「先跑通」为由运行合成 TTS、BGM、图生视频、成片拼装的脚本。
- **授权闸是单点的**：授权一旦失效或被撤回，相关脚本立即停跑；已生成的产物按 Q92 处置（保留不删、标记用途、不得作为出片素材）。
- **不得以「下游需要」倒推授权**：例：某条契约需要实测音频时长来定稿，**不能**因此就合成音频 —— 应改为「按标称网格声明 + 标注该轴未测」，把合成留给用户在出片阶段执行。

## 二、输入契约

输入**只有两样**，缺一不可：

1. **创意（Idea）** —— 一段话到一页纸。至少含：logline 候选、题材、目标平台、集数、单集时长、目标受众、参考作品、不可触碰的底线。
2. **大纲（Outline）** —— 分集梗概或篇章结构。允许粗，但**每集必须至少有一个"事件"和一个"钩子"**。

缺项处理：企划合规（群管理员）建 `D01 创意接单卡`，把缺口显式标为「待用户确认」。
**商务参数（集数 / 单集时长 / 平台 / 受众 / 付费卡点）不得自行脑补**，必须回问用户；
故事性缺口（人物动机、篇章转折）可提方案，但必须标注「方案，待用户拍板」。

> **上游素材可改（2026-10-22 用户授权）**：`双相潮主/01_漫剧策划/` 已放开写权限。
> 变更原则：**改源素材，保持单一真源**——设定改动直接改 `setting_db.json` / `story_spine.json` /
> `脉络确认.md` / `逐集内容概述.md` / `设定待核对清单.md`，不在工厂侧另建覆盖表。
> 改完必跑两件事：① 交叉校验（beat 集号以 `逐集内容概述.md` 的〔Bxx〕标注为准）；
> ② 工厂 `validate.mjs`。
>
> 仍保持只读：WeChat 容器内的上游收件箱副本（`.../msg/file/2026-10/`）、`双相潮主/00_长篇小说企划/` 白皮书正文、
> `吃鬼的男孩/` 全部素材。
>
> **变更须有依据**：设定改动只能来自 ① 用户拍板 ② 上游合规裁决（D03）③ 已确认的剧情逻辑。
> 不得凭猜测改设定。

## 三·五、单元制滚动生产

**单元 = 8 集**（U01–U20）。生产按单元滚动，**不并行铺全季**。

**单元锁 = 四条同时满足**：

1. 单元内 10 份交付物 JSON **齐全**；
2. `validate.mjs` **全绿**（V1–V11 无 error）；
3. **人工审读**通过（企划合规按第三节验收点逐条打勾）；
4. **承接钩子链验证**：本单元末集 `hook_out` 能接上下一单元首集 `hook_in`。

**D14 专项放行条件（v2.1 新增 · 与第 2 条并列，不替代它）**：

- D14 必须**逐镜覆盖** D11 的全部镜头——`(ep, shot_id)` 集合**恰好覆盖**（不多不少不缺）；
- 每镜的 `global_shot_no` / `scene_code` / `duration_sec` 与 D11 对应镜**一致**；
- 每镜的**逐镜包文件真实存在**（文件在 + 按 `D14ShotPackage` 校验通过）；
- **单镜样例不得充当单元完成**——只交 1 镜的样例不满足覆盖条件，不能锁单元。

以上由 **V11** 自动判定，缺失/多余/不一致一律报 **error**（不是 warning）。

**未锁的单元不得开下一单元。** 单元锁由企划合规登记进 D18。

**验收口径（2026-10-22 18:45 企划合规补充 · 澄清本条第 2/3 条的关系）**：
第 2 条 `validate.mjs` 全绿是交付的**必要条件，不是充分条件**。校验器只查结构与算术 —— V1 看字段与枚举、V3 看镜号连续、V4 看时长相加，**不读内容语义**。
实测反例：结构占位壳（含「全部镜头时长相等、画面描述一字不差同为一句」的空壳分镜）**校验返回 exit 0 / 通过 10/10 / error 0**。
因此：**第 3 条「人工审读」是唯一放行闸门**。bot 自检表与校验器绿灯**都不作为验收依据**；企划合规必须逐单元扫描字段覆盖率（脚本扫 + 人工语义审）后才可放行。

## 四·五、JSON 真源与单向渲染（v2.0 新增 · 强制）

**这是 v2.0 的核心变更。**

1. **JSON 是唯一真源。** 每份交付物先写成 JSON，落 `shared/` 或 `units/<UNIT>/`。
2. **Markdown 是产物，不是源。** 由 `render-md.mjs` 从 JSON 渲染生成。
3. **单向**：`JSON → MD`。**绝不**做 MD → JSON 反向同步。人工改 MD 会在下次渲染被覆盖。
4. **人工修订必须改 JSON**，然后重跑渲染器。

```bash
# 渲染（JSON → MD）
node 短剧文档工厂/04_工具/render-md.mjs --project 短剧文档工厂/02_项目/<项目名>

# 校验（每份交付物出口必跑）
node 短剧文档工厂/04_工具/validate.mjs --project 短剧文档工厂/02_项目/<项目名> --unit U01

# 全项目体检（可选；**v2.4 起为逐单元独立校验**，错误按单元分节、summary 合计）
node 短剧文档工厂/04_工具/validate.mjs --project 短剧文档工厂/02_项目/<项目名>
```

> **单元作用域（v2.4 · 强制）**：无 `--unit` 的跑法**不是**「把所有单元合并成一份交付物一起校验」，而是**逐单元各自独立校验**（共享层文档在每个单元轮次都会检查），错误**按单元分节**呈现、summary 为各单元合计。**禁止跨单元合并成一张以 doc_id 为键的表** —— 那样会让单元作用域规则（V3/V4/V8/V10/V11）失去作用域，且在后单元产出同名交付物后会产生**假绿**（Q52／OPS-13）。

**出口硬校验（v2.0 强制）**：任何交付物**落盘后必须跑校验器并全绿**，才算交付完成。
校验不过 = 交付物不存在，不得进入下游，不得在群里报「已完成」。

**字段规格**：`03_规格/字段规格表.md`（人读）+ `03_规格/schema.json`（机读）。
**可调阈值**：`03_规格/rules.json`（改它不改代码）。

## 六、白模流程（白模场景师专用，强制走 blender-h3-dcc 技能）

白模是最终视频的**时空合同**：它锁死镜头、切点、相机轨迹、动作时序、场景布局、相对位置、可见性、遮挡与光照空间关系。H3 之后只换外观，不改结构。

**逐镜交接（v2.1 新增 · 强制）**：白模与 H3 交接是**逐镜**的，**每镜一份独立交接包**。
H3 单次生成受帧数格点（17n+5）限制，一个 45 秒单元不可能一次生成（如 U01 有 32 镜），
因此**不存在「一个单元一份合同」这种东西**——单元级单份合同在结构上无法表达逐镜状态。
单元交付物 **D14 是这些逐镜包的索引 + 汇总**：`shots[]` 逐镜内联完整合同（`preflight`/`render_contract`/`appearance`/`h3_prompt`），
并用 `package_path` 指向落盘的独立包文件（`units/<UNIT>/D14_shots/ep<NN>_shot<NN>/package.json`）以便逐镜审计。
`commands` 是**字符串数组**，`check_results` 是**对象数组**，两者类型不可互换。

**六阶段（不得跳步，脚本未通过不进入下一阶段）**：

1. **定位素材** — 取 `mcode-dcc-inbox/<时间戳>/preview_video.mp4` + 同目录 `manifest.json`；没有就让用户先从 Blender 发白模。
2. **Preflight 与 Render Contract** — 跑 `m3_render_workflow.py preflight` 生成 `preflight.json` / `render_contract.json` / `appearance.json` / `source_anchor_frames/`；M3 **完整看完源视频**后逐项填写合同；再跑 `check-contract`，**失败就改 JSON，不得绕过**。
3. **全场景风格合同** — 填 `appearance.json`：`style_source_summary`、`reference_routes`（`style_only` vs `identity_and_style`）、参考图结构支配门、`global_style_bible`、`entity_appearances`。
4. **生成 H3 prompt** — 只用 `build-prompt` 脚本产出的 `h3_prompt.txt`，**不手写、不裁剪、不二次优化**；确认 `within_budget/protected_content_valid/ready_to_submit` 均为 true、字符数 ≤ 6500。
